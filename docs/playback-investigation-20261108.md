# macOS 偶发 404 与等待时间排查

依据本次提供的 `debug.log`（602 行）、`playback.log`（2760 行）、日志开关及安全配置分析。播放日志范围为 2026-11-08 13:25:13–13:50:30 UTC，跨多个进程；旧记录也包含其中，不能当作单次复现的故障率。

## 已确认的现象

- `debug.log` 的 404 来自首页、分类、播放地址、帖子、排行榜等业务接口，正文为 nginx HTML 错误页。全部业务请求经过 `/api/edge/request`；这与下载视频清单/分片是不同环节。
- 媒体代理完成的 10 次清单、78 次分片/密钥请求都为 HTTP 200；未记录媒体 404 或致命 HLS 错误。首页和吃瓜详情均有真实播放记录。
- 9 次用户定位全部有匹配的首帧恢复，未出现定位超时。耗时为 1518、2986、430、547、1118、818、2401、1953、1282 毫秒，包含 8 次点击、1 次拖动，中位数 1282 毫秒。
- 最慢一次定位：13:44:09.656 发起，约 3 毫秒后开始请求目标分片，下载 2603 毫秒，约 10 毫秒后完成入缓冲，2986 毫秒时收到首帧。剩余等待主要发生在分片下载阶段。
- 三次播放器从加载源到首个 `playing` 分别约 3.68、3.35、4.62 秒。这不包含获取业务数据/播放地址的等待；吃瓜详情还需要用户点击播放，不能把进入详情到播放器挂载的整个间隔视为 API 耗时。
- 64 个分片从 `hlsFragLoaded` 到 `hlsFragBuffered` 的中位数为 11 毫秒，最大 77 毫秒。该样本没有显示分片入缓冲是主要瓶颈；它不等同于测量界面帧率。
- 图片网络尝试中位耗时约 1.55 秒，最长 3.63 秒。10 次图片传输失败随后重试恢复，图片代理最终返回 200；这批日志没有图片 HTTP 404。
- 已观察到切出首页时暂停和停止加载；未发现 `active: false` 且 `paused: false` 的播放器快照。严格模式开启和关闭时都有成功播放，未记录安全拒绝事件。

## 当前不能确定的部分

旧版业务 API 失败只有无时间戳的 `debug.log` 错误，没有请求编号、线路和尝试耗时。因此不能把这批 404 精确对应到某条线路、安全模式或一次点击，也不能仅凭 nginx HTML 判定是源站部署、CDN 路由、某个后端节点还是代理路径的问题。`security.json` 仅表示导出时的配置，不能代表全部历史请求。

现有网络自检/线路测速只检查站点首页，HTTP 200 不能证明业务网关正常。不能凭主页可达就认定线路可用，也不能保证切换固定线路一定恢复。

## 本次客户端修正

1. HTTP 404、不可重试的 4xx、权限和安全拒绝直接结束；保留只读请求对超时/暂时性状态的有限重试，避免重复请求确定失败的资源。
2. 首页接口失败后结束转圈，提供明确重试；HTTP 错误提示保留状态码并隐藏网关 HTML。
3. 分类首次打开才请求预览；每个频道和帖子独立显示结果、错误及重试，不再等所有频道后再请求帖子、一起展示。
4. 相同开关下增加 `api.begin/end` 与 `line.changed`：记录时间、进程、请求/尝试编号、操作类别、主机名、HTTP/业务状态、响应类型、网关类别和耗时，不记录账号、搜索词或响应正文。
5. 尚未到达首字节/下载结束时，HLS 分片计时记录 `null`，修正原日志里的负耗时。

持续 5xx/超时仍保留最多三次、每次 20 秒的策略；这些修正不能消除上游故障或保证真实 CDN 下载提速。媒体代理目前先接收完整分片再返回给 WebView，因此 HLS 的首字节耗时包含 Rust 下载完整分片的等待，应结合 `network.end.headers_ms/elapsed_ms` 分析。

## 验证与后续采集

`pnpm test:api-loading` 在无头浏览器内注入 404/503/慢请求/空结果，验证页面状态、各频道独立更新/重试、隐藏分类不预取；Rust 网络测试验证重试策略。`pnpm test:playback --scenarios seek,legacy` 继续验证真实视频点击/拖动和分片计时。测试不访问上游，不能替代 macOS WKWebView/真实 CDN 验证。

实机使用新构建开启诊断日志、重新启动应用，复现一次首页失败与一次成功播放，并手动重试失败频道；保留当前及轮转日志。新的 `api.end` 能直接显示哪条线路、哪个业务操作、哪次尝试返回 404/503，以及等待时间。要继续优化传输，应先用新日志区分网关耗时、分片响应头等待与正文下载；本次不凭这些样本调整安全策略或回退 hls.js。
